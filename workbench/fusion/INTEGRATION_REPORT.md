## 五个问题怎么处理

### 1. 不再要求退回旧后端

原 `server.py` 要求后端提交必须等于 `312f137`。现在默认使用工作台所在仓库，
通过 `evaluation/compatibility.py` 的软件接口版本和能力检查确认入口可调用，
并检查实际导入模块所在位置，防止导入电脑上另一份同名代码。

`server.py:37` 的 `upstream()` 连接共享入口；`:59` 的 `source_snapshot()` 读取真实 Git 状态；
`:204` 的 `_check_runnable()` 拒绝未提交的已跟踪修改及服务启动后的版本切换。
每次新任务保存当前源码来源，后端原有的模型、求解器版本与哈希记录继续生效。
软件接口版本不表示算法通过论文一致性验证。

### 2. 整轮只有一个截止时间

`server.py:398` 的 `_execute_suite()` 只建立一次截止时间。每个电路使用
`截止时间 - 当前时间`，不会重新拿到完整限时。
模拟时钟案例实际记录的两个允许时长为 **30 秒、10 秒**。
时间耗尽后，后面的电路保留 `not_started_after_timeout`。
进程终止宽限为最多 30 秒；最终分析所花时间另计。

`server.py:436` 的 `_terminate()` 复用后端现有 `stop_group()`。
即使主进程先退出，也继续清理该组内可能残留的进程，避免两套取消规则逐渐分叉。

### 3. 先记全计划，再开始执行

`server.py:274` 的 `start_suite()` 在开线程之前保存全部电路；
新增共享 `suite_analysis.py:20` 的 `freeze_suite()` 保存配置、各电路完整任务列表、
参考摘要哈希以及套件整体计划。未运行的电路也已经有预定输出位置。

取消检查实际留下一个 `cancelled` 和一个 `not_started_after_cancelled`；
两个电路、每个两个种子的四条记录全部保留，没有再出现 `KeyError: 'manifest'`。
超时、启动错误、服务重启和返回成功却没有实验清单，也分别有明确状态。
没有估计就是没有估计，不能填失效率 0。

### 4. 网页和命令行使用同一个复算路径

新增 `suite_analysis.py:44` 的 `load_suite()` 核对整套计划、配置、参考和真实执行清单。
删除某个电路、改门限或改路径，都不能绕过冻结计划检查。
`:96` 的 `suite_groups()` 复用既有 `analyze_group()`，没有另写一套均值、误差或评分。
原后端 `analyze_results.py:416` 的 `analyze()` 只增加套件分派，旧 `groups` 入口保留。

实际离线复算保留了 `1e-8` 低权重估计、`1.2` 超 1 估计、候选不足无估计，
网页导入与直接调用共享分析器得到同样的分析对象。
跨电路各自成组，不能把不同目标混起来给一个总排名。

`suite_status.json` 是执行状态记录，可在运行中更新；配置与任务列表另用哈希冻结。
它记录的是执行状态，不替代每个运行的估计、成本和来源证据。
旧 Fusion 的仅含 `suite` 路径列表的清单缺少完整冻结计划，本次不替它补造历史任务。

### 5. 启动和测试不再找私人目录

新增 `start.sh` 根据脚本位置定位仓库，使用已激活的 Python 或 `OPENYIELD_PYTHON`。
`start.ps1` 可指定 WSL 发行版、仓库、Python 和端口；不再写死用户名与私人审计依赖目录。

原 13 个服务端回归改用 `tests/fixtures.py` 在临时目录生成小型模拟证据，
固定示例数值是测试数据，不是新增的 SRAM 结果。
新增 `test_integration.py` 检查套件限时、取消、复算、来源和坏结果保留。
浏览器检查改为读取公开只读演示，不再借用隔壁项目的 Node 包或私人实验记录。

导出脚本也改为明确指定新的目标目录，已经存在就拒绝，保留仓库历史演示。
原演示包、静态站点和截图与同学分支逐文件核对没有改动。
