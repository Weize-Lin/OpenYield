# 可复现流程验收基准

**状态**：配置和启动命令已准备，正式电路仿真待确认。本案验证其他研究人员能否从公开源码、锁定配置和环境得到可审计的五算法报告。单工况、单预算档位的输出用于验收流程。

## 固定工况和种子

- 电路为 1×1 6T SRAM，目标单元 `[0,0]`，保持静态噪声裕量，TT、1 V、27 ℃，全真实模式。18 维自定义参数按相对标准差 5% 的工艺分布抽样，迁移率为正。保持裕量小于 327.65 mV 记失效，门限沿用历史对照设定。
- 独立参考用 8311–8314，每个种子 256 条直接 MC，共 1024 条。比较用 9101–9108，每方法每种子最多 48 条，共 1920 条。总上限 **2944 条提交给 Xyce 的参数行**。
- 这些种子的历史结果已知，用于复跑流程。当前统一入口的随机数实现与旧脚本可以不同，验收保留实际坐标和结果。若研究策略改动是否改善精度，须另预先登记新种子和独立参考。比较配置在查看本次参考结果前即规范化、保存并计算哈希。

[参考配置](hold_workflow_cases/reference.json) · [比较配置](hold_workflow_cases/comparison.json) · [启动脚本](run_hold_workflow.sh)

## 策略和停止条件

| 方法 | 身份和候选策略 | 正式提议与批次 |
| --- | --- | --- |
| MC | OpenYield 当前直接 MC，登记为 `reference`。无初始化与复测。 | 原工艺抽样，每批 8 条。比较 48 条，独立参考 256 条。 |
| MNIS | 当前 `variant`，取得首个失效点作为中心，复测一次。 | 各坐标用目标工艺方差，标准差倍数 1，外层原工艺混入比例 0，每批 1 条。 |
| AIS | 当前 `variant`，首个失效点进入大小为 1 的初始池，复测一次，按现有规则更新中心。 | 沿用对角标量方差 (10^{-5})，标准差倍数 1，外层混入比例 0，每批 1 条。 |
| ACS | 当前 `variant`，首个失效点进入大小为 1 的初始池，复测一次。后续追加正式失效点，沿用当前未启用聚类的实现。 | 沿用对角标量方差 (10^{-5})，标准差倍数 1，外层混入比例 0，每批 1 条。 |
| HSCS | 当前 `variant`，首个失效点进入大小为 1 的初始池，复测一次，从名义坐标搜索。同工况搜索最多 8 条，无辅助写。 | 沿用对角标量方差 (10^{-5})，外层混入比例 0，保留算法内部 10% 的名义中心高斯，每批 1 条。 |

四种重要性抽样都使用名义值周围的 ±3σ 均匀盒初始化，每批 4 条，达到至少一个失效点即停止，最多提交 12 条。超出初始化限额仍找不到点时，保留候选不足状态。每方法每种子，算法请求与实际仿真均设上限 48，初始化、复测、搜索和正式抽样都占相应成本。正式批次用剩余额度，预算放不下整批即停。流程使用严格预算，FOM 留作诊断。MNIS 的零目标密度样本按已有规则计请求并留在估算分母，其他三个算法碰到支持域外样本时保留现有未完成状态。

## 运行资源、超时和中断

| 资源 | 预算 |
| --- | --- |
| 并发 | 串行，一次一个算法种子、一个 Xyce 进程，CPU 线程设为 1 |
| 时间硬上限 | 参考阶段 10 分钟，比较阶段 50 分钟。阶段超时后至多 30 秒宽限再终止进程组 |
| 历史耗时依据 | 同一工况旧留档 44 条运行，逐行墙钟时间合计 1374.989 秒，约 23 分钟，其中参考约 2 分 16 秒。预算设置有变化，预估 20–35 分钟，仅供安排 |
| 磁盘 | 历史留档约 541 MiB。启动前至少需 4 GiB 可用空间，用于日志及求解器重试保留件。此项是预检查，不是文件系统配额 |
| 样本和重试 | 上限 2944 个预算样本。内置数值恢复只对同一批、同一参数重求解，保留首次失败证据。按每批最多原尝试加两种数值重试保守估算，最多 8832 个参数行尝试。保持裕量的直流网表没有瞬态步长恢复路径 |

脚本不重启失败种子。现有 `utils/xyce.py` 可针对 DC 工作点失败重试一次，含瞬态分析时还可对步长过小做一次恢复。内置重试增加实际计算时间，输入参数行不重复扣算法预算。参考阶段失败或四份摘要不完整就停在参考检查，比较阶段的普通单条失败照常留在执行计划。超时状态、原日志和已写出的报告保留。手动中断后用冻结清单离线分析，未产生摘要的条目仍计入原计划；不在相同目录补跑或覆盖证据。

## 启动前检查

用包含本配置的干净 checkout 和仓库 `environment.yml` 安装的 Python 环境。启动脚本会记录实际 Git 提交和工作区状态、求解器完整版本与文件 SHA-256、TT 模型和环境清单的 SHA-256、依赖版本，以及两份规范化配置的 SHA-256。求解器指纹是整次实验的运行前证据，历史摘要里只有路径时仍保留版本未知的标志。上次干净环境验证所见为 Xyce `DEVELOPMENT-202312200606-(Public_Release-7.4.0-36-gb7bb12d8)-opensource`。实际运行以现场保存的指纹为准。

预检命令只整理配置和版本信息：

```bash
conda activate openyield
bash docs/research/run_hold_workflow.sh preflight outputs/hold_workflow_preflight
```

审定策略和资源预算后，用一个新目录运行：

```bash
bash docs/research/run_hold_workflow.sh execute outputs/hold_workflow_qualification
```

输出包括运行前指纹、阶段状态、独立参考检查表、参考摘要哈希、完整比较计划和逐运行表。验收核对计划中 40 条比较任务全部有条目，失败与未完成均可定位，独立参考与目标一致，原始估计、告警和成本能够回查。描述性误差连同参考不确定度一起报告。
