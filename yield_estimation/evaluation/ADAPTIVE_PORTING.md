# AIS、ACS、HSCS 接入说明

这次做的是让仓库里的算法共用一套电路配置、仿真接口和结果记录。不是把几种算法重新写一遍，也不是已经做出了可信的算法排行榜。

## 现在从哪里开始

统一入口是 `yield_estimation/evaluation/run_diagnostics.py`。在 WSL 的仓库根目录、openyield 环境下运行。先预览，不会启动仿真：

```bash
python -m yield_estimation.evaluation.run_diagnostics \
  --config yield_estimation/evaluation/cases/read_3x2_porting_smoke.json \
  --algorithms mc mnis ais acs hscs \
  --proposal-variance 0.000001 \
  --allow-hscs-mixed-search \
  --output-dir outputs/my_five_algorithm_check
```

确认后在同一命令末尾加 `--run-xyce` 才会运行。每次换一个不存在的结果目录。上面是用法示例，不表示这条五算法命令已经整体执行过。

`--algorithms` 后写哪些名字就运行哪些算法。所有算法读取同一份电路、工艺和门限配置。原始配置还会复制到结果目录的 experiment.json，防止运行过程中手动改配置导致前后条件不同。

这份示例是 3×2 6T、TT、1V、27℃、5%相对工艺波动、正迁移率、读门限0.7ns、每种算法12条预算。它故意容易出现失效，用来检查流程；0.7ns不是推荐的芯片设计指标，12条也不足以评价算法精度。

`--proposal-variance` 控制 AIS/ACS/HSCS 在选定位置周围抽多散，不改变大家共同要估算的工艺分布。这里的 0.000001 是本次接入测试明确选择的设置，不能把它说成算法原作者的默认设置。MNIS不使用这个参数，仍保留其原有提议分布。

## 为什么 HSCS 要额外说明读写

代码实际做了三件事：

1. 读 `[1,1]` 单元，找出初始读失效样本。
2. 在寻找抽样位置时，改测阵列最后一个单元的写操作；3×2时是 `[2,1]`。写结果帮助它决定接下来在哪里找。
3. 找完位置后，又读 `[1,1]`，用这些读结果估算读失效率。

方括号里的编号从0开始。这条读—写—读流程在老师指定版本的历史源码中已经存在，不是这次新加的。

中间用写测试帮忙选位置，不等于最终估算的是读写混合良率。最终计分对象仍然是读。辅助测量能否有效帮助找点，需要另外验证，不能仅凭混用就断定理论错误或正确。

为了避免用起来误解，必须显式加 `--allow-hscs-mixed-search`。写测试同样耗预算，但单独记在 auxiliary_write_samples.csv，不混进读失败数，也不加入最终读估算的分母。沿用原代码的同一门限进行辅助搜索；没有另做写良率研究。

这次没有把 HSCS 的 write 改成 read，没有重新设计球面搜索，没有缩小或放宽电路安全门限，没有偷偷补抽非法样本。AIS/ACS的初始化均匀抽样和中心更新逻辑保持原来方法。所做兼容修复必须与运行参数一起披露，因此不能称为完全未改动的原始代码。

## 首次 HSCS 真实运行为什么停了

Xyce算出了写延迟0.09464082ns，但位线恢复误差0.02736296V超过原代码的0.02V限值。原接口把它标成失效、将延迟置空，随后又按缺测报错。

现在只有完整电压证据确认不合格，才作为写访问失效交回算法。缺少证据、求解器失败，仍然停止并保留现场，不能随便当成电路失效。这个处理通过新增 retain_write_failures 开关启用；旧调用默认行为不变。

## 看哪些结果

- report.md：先看状态、实际提交/返回数、阶段计数和数值状态。
- run_summary.json：精确值、配置、代码哈希、各阶段成本。
- samples.csv：实际读仿真及判定；HSCS辅助写另在 auxiliary_write_samples.csv。
- estimation_draws.csv：真正参与估算的样本和权重所需数据。初始化与复测不算在这里。
- batch_*/：真实样本、网表、电压测量和 Xyce 输出。
- 多算法运行的 collection/report.md、summary.csv：汇总对照。失败、下溢都保留，不生成排名。

`underflow` 是普通数字存不下这么小的估计，应看 log10(Pfail)，不是“零失效”。小样本、极小权重和少数点主导结果都可能使估计不可靠。程序跑完只是完成了接入检查。

后续应固定正式工况、预算和重复种子，建立有误差范围的MC参考，再评价算法误差与成本。不要为了让结果接近MC而不断改动某一种算法，然后仍称其为原始算法。
